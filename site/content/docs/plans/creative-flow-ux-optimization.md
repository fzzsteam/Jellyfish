# 创作流程体验优化计划

本文记录仍在推进中的创作流程体验优化方案。它描述接下来要做什么，归属 `plans`；已稳定落地的页面职责和状态语义应在实施后同步沉淀到 `architecture`。

## 目标

- 让新用户进入平台后能理解从项目到视频生成的主流程。
- 让已有项目清楚显示下一步动作，减少用户在页面间试探。
- 保持分镜准备与生成工作室的职责边界。
- 保持 `shot.status`、runtime task status、`video-readiness` 三类状态语义分离。
- 第一阶段尽量不新增后端 API，不新增手写前端 service。
- 吸收公司成员反馈，优先改善按钮与引导不清、工作室过于复杂、一键批量生成路径不够突出的问题。

## 第一阶段范围

第一阶段采用“主流程纠偏 + 下一步推荐”，暂不实现完整新手 Wizard。

核心流程为：

```text
项目大厅 / 项目工作台
  -> 章节原文
  -> 分镜提取并自动准备资产与对白
  -> 分镜准备页检查与补缺
  -> 分镜工作室生成
  -> 任务中心追踪轻量运行状态
```

## 成员反馈映射

公司成员需求汇总中提到的优化点会按阶段处理：

- 初始页面复杂、按钮不够明显、用户不知道下一步点哪里：纳入第一阶段，通过下一步推荐、空状态行动卡和更清晰的主按钮处理。
- 分镜准备需要逐镜头点击“提取并刷新候选”：纳入第一阶段，章节分镜提取任务完成后自动提取资产 / 对白候选，并自动关联已有图片资产。
- “分镜工作室”画面过于复杂：纳入第一阶段，通过折叠次级维护动作、突出生成主线处理。
- 希望一键生成每条分镜视频，只修改效果不好的视频：纳入第一阶段，强化 ready 镜头的一键批量生成入口与结果回看。
- `happyhorse-1.0-r2v` 支持最多 9 张参考图但前端体验不足：列入后续能力轨道；若现有 API/generated types 已支持则在实施中并入，否则按 API 变更流程推进。
- 需要更多风格或图片参考：列入后续能力轨道，结合供应商能力和项目风格配置设计。
- 资产图片生成不应覆盖旧图，应列出所有结果供选择：列入资产管理增强轨道，先判断当前是 UI 展示问题还是持久化契约问题。
- 资产管理批量上传本地图片：列入资产管理增强轨道，可能需要文件/资产接口协作。

## 页面职责

### 项目大厅与项目工作台

项目入口负责判断项目或章节下一步动作，并把用户送到正确页面。

计划调整：

- `edit_raw` 进入章节编辑。
- `extract_shots` 进入分镜列表并提取分镜。
- `extract_shots` 提取分镜后自动准备资产与对白，减少逐镜头手动刷新。
- `prepare_shots` 进入分镜准备队列或下一个待确认镜头编辑页。
- `shoot` 或已就绪章节进入分镜工作室。

### 分镜列表页

分镜列表页作为章节分镜准备队列。

计划调整：

- 增加章节流程提示：原文、分镜、准备确认、生成。
- 主行动根据状态变化：
  - 有 pending 镜头时，处理下一个待确认镜头。
  - 全部 ready 时，进入工作室生成。
  - 有运行中任务时，显示轻量任务提示与回跳。
- 明确区分信息确认状态和运行时任务状态。
- pending 选择进入准备页，ready 选择进入工作室。

### 分镜编辑页

分镜编辑页继续作为准备主入口。

计划调整：

- 展示基础信息、资产候选、对白候选、确认状态的紧凑准备卡。
- 分镜提取后的候选会先由系统自动准备；本页主要处理缺图、低置信、多候选或需要人工修正的内容。
- 根据当前缺口推荐编辑 tab。
- 当前镜头 ready 后，引导处理下一个待确认镜头。
- 本章准备完成后，引导进入分镜工作室。

### 分镜工作室

分镜工作室继续作为生成工作区。

计划调整：

- 默认优先选择 ready 或正在生成的镜头。
- 没有 ready 镜头时，显示返回准备页的主行动。
- pending 镜头只保留诊断和返回准备页入口，不作为主要确认入口。
- 折叠维护类、调试类和低频高级配置，让首屏优先呈现视频准备度、生成主行动和结果回看。
- 视频准备度失败时解释缺口，但不改变 `shot.status`。
- 批量生成优先处理 ready 或可生成镜头，并说明被跳过的 blocked 镜头。
- 为“本章 ready 镜头一键生成视频”提供更清晰入口，生成后让用户优先回看结果，只对效果不佳的镜头重试或修改。

### 任务中心

任务中心继续作为通用任务状态面板。

计划保持：

- 展示任务状态、进度、取消、回跳入口。
- 不展示提示词调试上下文、图文映射细节或业务专属摘要。

## 数据与状态约束

- 前端调用继续使用 OpenAPI generated client。
- 不新增手写 service 封装。
- `shot.status` 只表示信息提取确认状态。
- 运行中状态来自任务系统和 runtime summary。
- 视频生成准备度来自 `video-readiness`。
- 如实施中需要后端 API 变更，必须同步后端、OpenAPI、前端 generated types 与对应文档。

## 实施阶段

1. 统一 next-action helper：集中阶段判断、文案和跳转意图。
2. 调整项目大厅与工作台推荐动作：`prepare_shots` 不再直接进入工作室。
3. 调整初始/空状态引导与主按钮：让新用户明确下一步，不实现完整 Wizard。
4. 调整分镜列表页：改为准备队列，并拆分信息确认与运行任务状态。
5. 调整分镜编辑页：补齐准备闭环和下一镜头/进入工作室出口，并将手动提取降级为修复入口。
6. 调整分镜工作室：默认聚焦生成，pending 镜头引导回准备页，折叠低频功能。
7. 强化 ready 镜头一键批量生成入口与结果回看。
8. 校验任务中心边界：保持轻量通用，不加入业务重上下文。
9. 更新已落地的 architecture 文档。

## 验证计划

实施后至少验证：

- 在 `front` 下运行 `pnpm exec tsc --noEmit`。
- `prepare_shots` 会进入准备队列或待确认镜头编辑页。
- 章节分镜提取完成后，会自动生成资产 / 对白候选并尽量完成可用资产关联。
- 分镜编辑页不再要求用户逐镜头点击“提取并刷新候选”作为主流程。
- pending 镜头不会被当作可生成状态。
- ready 镜头能进入工作室生成。
- 工作室默认不优先选中 pending 镜头。
- 初始页、空项目、待准备章节都有清晰主按钮和下一步说明。
- 工作室首屏不被维护/调试/低频高级功能淹没，ready 镜头可通过明确入口批量生成。
- 任务中心只展示通用任务信息。
- 未修改 API 时不运行 `pnpm run openapi:update`；若修改 API，则必须运行。

## 后续阶段

完整新手 Wizard 和生产指挥中心暂不进入第一阶段。主流程稳定后，可以再评估：

- 首次使用的轻量引导或检查清单。
- 跨章节批量准备与批量生成队列。
- 更高层的生产指挥中心。
- 多参考图视频生成能力，包括 `happyhorse-1.0-r2v` 的最多 9 张参考图体验。
- 资产图片历史结果选择，避免用户感知为“生成第二张覆盖第一张”。
- 资产管理批量上传本地图片。
- 更丰富的 AI2D、AI3D 等视觉风格和图片参考配置。
