> 本文属于“当前架构”文档，描述当前已经生效的页面职责边界。

## 背景

随着 `shot.status` 收窄为：

- `pending`
- `ready`

并且 `video-readiness` 成为独立的生成准备度检查，分镜相关页面也需要明确区分：

- 哪一页负责章节级队列与批量动作
- 哪一页负责单镜头准备与生成

如果这两层边界不清晰，页面很容易重新长成“两个都能做一点”的混合大页。

## 核心结论

当前真实生效的页面分工是：

```text
ChapterShotEntryPage (/shots)
  = 章节分镜入口 / 空态兜底

ShotDetailPage
  = 单镜头主工作区

/studio
  = 兼容跳转入口
```

也就是：

```text
分镜入口
→ 有镜头时直接进入首个镜头详情
→ 无镜头时只保留“一键提取分镜 / 新增分镜”

镜头详情
→ 左侧镜头队列、基础信息、提取确认、生成视频、视频结果
```

## 分镜入口页的职责

`/shots` 不再承担旧的章节镜头列表职责，而是收敛为一个轻量入口页：

- 章节已有镜头时，直接跳转到首个镜头详情。
- 章节还没有镜头时，只展示：
  - `一键提取分镜`
  - `新增分镜`
- 这页不再承载章节级镜头浏览、批量生成、批量下载和批量诊断。

## 资产管理图片候选池

资产管理页负责图片生成结果的沉淀与挑选。资产图片槽位的 `file_id` 只表示当前采用图；生成任务返回的所有图片会作为候选图保留在对应槽位的候选池中。

当前行为：

- 当前图为空时，生成结果中的第一张会自动成为当前图。
- 当前图已有值时，新生成图片只进入候选池，不覆盖当前图。
- 资产管理列表页的“新建”入口会创建带唯一草稿名的最小草稿资产并直接进入资产编辑页，基础信息统一在编辑页维护。
- 演员、场景、道具、服装名称保持全局唯一；用户在编辑页点击“生成”时若发现名称重名，会返回冲突提示而不是继续创建生成任务。
- 资产管理列表页的本地批量上传会创建新资产，上传图片成为新资产当前图，并同步进入候选池，来源显示为“本地上传”。
- 资产编辑页不承载本地上传入口，主要负责单个资产的图片生成、候选回看和显式采用。
- 用户可以在候选池中显式选择“设为当前图”。
- 候选池属于资产管理职责，不进入任务中心，也不改变 `shot.status`。

## 镜头详情页的职责

镜头详情页是当前单镜头主工作区，按四个步骤组织准备与生成。

### 四个步骤

1. `基础信息`
   - 维护标题、剧本摘录、镜头语言、时长、动作拍点等基础真值。
2. `提取确认`
   - 处理自动准备后仍待确认的资产 / 对白候选。
   - 必要时重新提取 / 刷新候选，作为修复入口。
   - 支持 `skip_extraction` 等准备决策。
3. `生成视频`
   - 展示 `video-readiness` 诊断。
   - 维护关键帧、参考图、视频提示词、生成参数与单镜头生成入口。
4. `视频结果`
   - 回看生成结果、选片、下载与重试。

### 左侧镜头队列

镜头详情页左侧不只是导航列表，当前已经承担轻量的队列与批量操作职责：

- `新增分镜`
- `一键提取分镜`
- `全部 / 未提取 / 待确认` 筛选
- 勾选框多选
- 当前筛选结果全选
- 顶部批量下拉菜单
- 右键单镜头插入操作

当前可从左侧直接发起的动作包括：

- 章节级：一键提取分镜、新增分镜
- 批量：提取、诊断、生成视频、下载视频、删除、标记无需提取 / 恢复提取
- 右键单条：向上插入、向下插入

这组动作的语义是：

- 点击镜头主体：只切换当前详情，不隐式勾选
- 勾选框：只维护多选集合
- 顶部下拉：只承接批量通用动作
- 右键菜单：只承接插入这类位置性动作

### 这页的目标

回答：

- 当前镜头的信息确认是否完成
- 当前镜头的视频生成还差什么
- 接下来应留在当前镜头继续生成，还是切到下一个待确认镜头

可以把这页理解成：

```text
单镜头准备与生成工作区
```

## 兼容 `/studio` 路由的职责

旧 `/studio` 路由当前只保留兼容跳转职责：

- 保证旧链接、旧入口和外部回跳不立即失效。
- 将用户落到当前镜头详情的相关生成步骤。
- 不再作为菜单主入口，也不再承担新的页面边界定义。

## 两页之间的推荐主流程

```text
项目工作台（默认章节）
→ 分镜入口
→ 镜头详情
→ 基础信息
→ 提取确认
→ shot.status = ready
→ 生成视频
→ 视频结果
```

如果在镜头详情的“生成视频”步骤中发现：

- `shot.status = pending`
- `video-readiness.extraction_ready = false`

则应回流到：

```text
镜头详情 / 提取确认
```

继续完成提取确认。

## 状态边界

为了让页面分工和后端状态一致，建议始终遵守下面这条规则：

- `shot.status`
  - 只表示信息提取确认状态
- `video-readiness`
  - 只表示视频生成前置条件是否满足
- runtime task
  - 只表示当前是否有运行中的生成任务

也就是说：

```text
准备状态
≠
视频可生成状态
≠
生成中状态
```

这三者应分别展示，不应继续混进同一个字段或同一类提示里。
