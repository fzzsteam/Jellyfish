# 项目入口与分镜流程重构设计

## 背景

当前 Jellyfish 前端存在多个互相重叠的入口：

- 项目列表的主按钮会根据项目状态跳转到分镜列表或分镜工作室，但文案和实际行为不稳定。
- 项目速览按钮命名为“进入章节工作室”，实际进入项目仪表盘。
- 项目工作台默认打开仪表盘，但章节 Tab 在视觉上更像主入口。
- 顶部导航把“分镜列表”和“分镜工作室”放在项目工作台同级，导致章节级页面被提升为全局入口。
- 分镜列表、分镜编辑页和分镜工作室都承载部分准备与生成职责，用户需要理解过多页面概念。

本设计目标是把主流程收敛为更少、更稳定的页面层级，并让镜头准备与视频生成在单镜头详情内闭环。

## 目标

- 项目入口只负责打开项目，不直接跳到章节级页面。
- 项目工作台默认进入章节流水线，用户从章节进入分镜列表。
- 分镜列表只作为章节镜头队列和批量操作入口。
- 分镜编辑页升级为镜头详情页，承载单镜头完整闭环。
- 原分镜工作室不再作为主入口，单镜头生成能力迁移到镜头详情。
- 批量生成、批量下载保留在分镜列表顶部工具栏。
- 用户界面不再直接暴露 `video-readiness` 技术检查项。
- 生成模式由视频模型能力决定，不向用户展示模型不支持的模式。

## 非目标

- 不在本阶段重做全局任务中心。
- 不在镜头详情内重复展示任务进度、任务失败原因和取消状态；这些仍由全局任务中心承担。
- 不新增完整跨章节生产指挥中心。
- 不删除后端兼容字段或历史路由；原工作室路由先保留兼容跳转。
- 不把纯文本生成作为主流程模式开放给普通用户。

## 页面层级

新的主路径为：

```text
项目列表
  -> 项目工作台（默认：章节流水线）
  -> 某章分镜列表
  -> 镜头详情（基础信息 / 提取确认 / 生成视频 / 视频结果）
```

### 项目列表

项目列表只保留项目级入口：

- 点击项目卡片主体进入项目工作台的章节流水线。
- 项目卡片按钮文案固定为“打开项目”，也进入项目工作台章节流水线。
- 项目卡片不再根据阶段直接跳转到分镜列表或分镜工作室。
- 右侧“项目速览”中的重复进入按钮删除。
- 项目列表保留项目阶段、项目统计和轻量摘要，不承担章节级操作。

### 项目工作台

项目工作台以章节流水线为默认页：

- 默认 Tab 从 `dashboard` 改为 `chapters`。
- Tab 名称使用“章节”，页面标题和空状态文案使用“章节流水线”强化主流程语义。
- `仪表盘` 降级为“总览”，只保留项目统计、资产健康等非主流程信息。
- 删除 Dashboard 中与章节流水线重复的入口：
  - 当前推荐动作
  - 当前待办卡片
  - 动态摘要
- 顶部全局导航移除“分镜列表”和“分镜工作室”，只保留项目级入口。

### 分镜列表

分镜列表定位为章节级镜头队列：

- 展示这一章的所有镜头。
- 每条镜头展示用户步骤状态，而不是直接暴露技术状态。
- 每条镜头只保留一个主按钮，点击进入镜头详情的对应 Tab。
- 章节没有分镜时，显示“提取分镜并自动准备”入口。
- 已有分镜时，不再把“进入工作室”作为主按钮。
- 顶部保留批量工具栏：
  - 批量生成视频
  - 批量下载
  - 后续可接入批量检查或任务中心优化

分镜列表不再展示单镜头的资产、台词、提示词和生成诊断细节。

### 镜头详情

分镜编辑页升级为“镜头详情”，用 4 个 Tab 承载单镜头闭环：

1. 基础信息
2. 提取确认
3. 生成视频
4. 视频结果

“分镜准备页”不再作为独立页面概念存在；准备工作拆入基础信息和提取确认两个 Tab。

### 原分镜工作室

原分镜工作室不再作为主页面入口：

- 顶部导航移除“分镜工作室”。
- 分镜列表和项目工作台不再把单镜头主流程跳到工作室。
- 第一阶段保留 `/projects/:projectId/chapters/:chapterId/studio` 兼容路由。
- 访问该路由时，若该章存在镜头，重定向到推荐镜头详情的“生成视频” Tab；若该章没有镜头，重定向到该章分镜列表。
- 确认无人依赖后，再单独删除旧页面代码。

## 镜头详情 Tab 设计

### 基础信息

负责镜头基础表达和生成前必要的镜头语言：

- 镜头标题
- 原文摘录
- 景别
- 角度
- 运动
- 时长
- 比例
- 动作拍点

完成条件：

- 标题和原文摘录非空。
- 镜头语言字段满足当前系统要求。
- 时长有效。
- 动作拍点存在。

### 提取确认

负责资产与台词确认：

- 资产候选确认、关联或忽略。
- 台词候选确认、接受或忽略。
- 缺失资产提示和跳转。

完成条件：

- 资产候选没有 `pending`。
- 台词候选没有 `pending`。
- 或镜头被明确标记为无需提取。

`shot.status=ready` 在 UI 中只表示“提取确认完成”，不再叫“已就绪分镜”。

### 生成视频

负责准备并提交一次视频生成：

- 选择视频模型。
- 根据模型能力显示可用生成模式。
- 准备该模式所需素材。
- 选择清晰度。
- 显示积分试算。
- 点击“生成视频”后进入提示词预览与积分确认弹窗。

生成视频 Tab 不展示 `extraction_ready`、`duration_ready`、`prompt_ready` 等技术检查列表。

如果前置条件不满足：

- 生成按钮置灰。
- Hover 或 Tooltip 展示最短阻断原因。
- 如“请先完成资产与台词确认”“缺少首帧”“请先设置时长”“视频模型未配置”。

点击“生成视频”后的提示词预览和积分确认仍是必经步骤。

### 视频结果

负责展示已成功生成的视频版本：

- 当前视频。
- 历史生成版本。
- 下载。
- 设为当前。
- 删除。

“设为当前”表示该视频是镜头当前采用版本：

- 分镜列表默认展示它。
- 批量下载默认下载它。
- 后续剪辑或导出成片默认使用它。

视频结果 Tab 不展示全局任务进度和失败原因。运行中、失败、取消状态后续统一在任务中心优化。

## 生成模式与模型能力

生成模式不能作为固定选项平铺给用户。前端应先根据视频模型能力决定可见模式：

- 只显示当前模型支持的模式。
- 不支持的模式不显示，也不以置灰形式占位。
- 普通用户主流程不开放纯文本生成。

面向用户的模式应是产品语言，而不是 `reference_mode` 技术 key：

- 首帧生成
- 首尾帧生成
- 参考图生成
- 多参考图生成

示例规则：

- HappyHorse i2v 类模型只显示其支持的图片转视频模式，例如首帧生成。
- HappyHorse r2v 类模型显示参考图或多参考图生成。
- 视频编辑类模型不进入当前分镜主流程。
- t2v 纯文本能力只可作为诊断或内部能力，不在普通主流程展示。

## 状态展示

前端列表统一展示用户步骤状态，不直接暴露 `shot.status`、任务状态和 readiness 技术项。

用户步骤：

1. 基础信息
2. 提取确认
3. 生成视频
4. 视频结果

状态映射原则：

- `shot.status=pending` 表示提取确认未完成。
- `shot.status=ready` 表示提取确认完成。
- 运行中状态来自任务系统，不写入镜头确认状态。
- `video-readiness` 只用于决定生成按钮可用性和阻断原因。
- 已有当前视频或成功视频版本时，列表展示“已有结果”。

分镜列表每行主按钮规则：

- 基础信息缺失：补基础信息
- 资产或台词未确认：确认资产与台词
- 生成素材缺失：准备生成
- 可生成：生成视频
- 已有结果：查看结果

点击主按钮进入镜头详情对应 Tab。

## 数据与接口

第一阶段优先使用现有 OpenAPI generated client，不新增手写 service。

预计不需要新增后端 API，但实施时需要确认：

- 当前视频模型能力是否足以驱动前端模式显示。
- 当前 generated video 结果列表是否满足视频结果 Tab。
- 原工作室中单镜头生成所需接口是否能在镜头详情复用。

如实施中发现需要 API 变更，必须同步：

- 后端实现
- OpenAPI
- 前端 generated types
- architecture 或 plans 文档

## 错误处理

- 生成按钮不可用时，只展示一个最关键阻断原因。
- 技术检查项默认不展示，可保留低频诊断入口。
- 生成提交前仍打开提示词预览与积分确认弹窗。
- 提交失败由现有错误提示处理，任务运行中状态由任务中心承接。
- 原 `/studio` 兼容路由不能 404，应跳转到可继续工作的页面。

## 测试与验证

实施后至少验证：

- 在 `front` 下运行 `pnpm exec tsc --noEmit`。
- 项目列表点击卡片和“打开项目”都进入项目工作台章节流水线。
- 顶部导航不再显示“分镜列表”和“分镜工作室”。
- 项目工作台默认打开章节页。
- 分镜列表每行只有一个主流程按钮，且能进入镜头详情对应 Tab。
- 镜头详情 4 个 Tab 可切换并保持 URL 状态。
- 未完成提取确认时，生成视频按钮不可用，并提示去确认资产与台词。
- 视频模型变化后，生成模式只显示该模型支持的模式。
- 点击生成视频会进入提示词预览与积分确认弹窗。
- 视频结果 Tab 能展示当前视频和历史版本。
- 批量生成和批量下载仍能从分镜列表顶部工具栏进入。
- 访问旧工作室路由会重定向到新流程，不出现空白或 404。
